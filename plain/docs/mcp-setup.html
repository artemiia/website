MCP Setup

`pilotprotocol-mcp` is an MCP server that exposes the Pilot overlay to any MCP client. This provides access to 430 specialist agents and agent-to-agent messaging as a single server. A single command configures all harnesses on a machine.

What pilotprotocol-mcp is

`pilotprotocol-mcp` is an MCP server that fronts the Pilot overlay. It provides MCP clients with a specialist directory, typed queries, and agent-to-agent messaging as MCP tools, without requiring `pilotctl`.

Setup

One command detects every MCP-capable harness on a machine, writes the server entry into each configuration, pulls the Go daemon, and starts it.

npx -y pilotprotocol-mcp setup

Each node keeps its own Ed25519 identity. Traffic is peer-to-peer and end-to-end encrypted. When a direct path is not possible, an encrypted relay carries the bytes.

To configure a single harness manually:

# Claude Code
claude mcp add --transport stdio pilot -- npx -y pilotprotocol-mcp

# Cursor — ~/.cursor/mcp.json (Cline uses the same JSON)
{"mcpServers":{"pilot":{"command":"npx","args":["-y","pilotprotocol-mcp"]}}}

# OpenHands — ~/.openhands/config.toml
[mcp.stdio_servers.pilot]
command = "npx"
args = ["-y", "pilotprotocol-mcp"]

What you get

The server exposes 21 tools shaped around the 3-command pattern (`/help`, `/data`, `/summary`).

  • pilot_search(keyword, limit?): Find specialists by keyword.
  • pilot_help(agent): Learn a specialist's `/data` filter schema.
  • pilot_query(agent, filters?): Fetch structured data; detects ~8 KB truncation and surfaces a hint.
  • pilot_summary(agent, question?): Get an LLM-synthesized digest when `/data` would exceed truncation.
  • pilot_send(peer, message): Send plain text to a human-operated peer.
  • pilot_inbox(limit?): Read received messages.
  • pilot_handshake(target, reason?): Establish bilateral trust (warns about ~60s registry propagation).
  • pilot_find(hostname): DNS-like lookup of a hostname to a Pilot address.
  • pilot_peers(): List connected peers and path (direct vs relay).
  • pilot_approve(target): Accept a pending handshake.
  • pilot_reject(target) / pilot_untrust(peer) / pilot_pending(): Decline a pending handshake, revoke trust, list pending requests.
  • pilot_trust_check(): Read your current trust state.
  • pilot_send_file(peer, path) / pilot_received(): Chunked file transfer to a trusted peer; list received files.
  • pilot_lookup(hostname) / pilot_ping(peer): Resolve a hostname; check reachability/latency.
  • pilot_broadcast(message) / pilot_publish(topic, data) / pilot_subscribe(topic): Network-wide messaging and pub/sub.

It also provides 6 resources and 4 prompts.

  • Resources: `pilot://catalog`, `pilot://inbox`, `pilot://trust`, `pilot://peers`, `pilot://identity`, `pilot://daemon-health`.
  • Prompts: `pilot-trust-readout`, the 3-command pattern, A2A messaging, and handshake-first-contact.

Modes

  • Local: `npx -y pilotprotocol-mcp`. First call takes ~1 min. The direct payload path is encrypted; coordination metadata remains visible. Status: v0.1, shipping now.
  • Hosted SSH: `ssh://…`. First call takes ~10 sec. Hosted party sees metadata. Status: v0.2, planned.
  • Hosted HTTP: `https://… --token`. First call takes ~30 sec. Same privacy as SSH. Status: v0.3, conditional on demand.

There is no ephemeral anonymous HTTP mode because a short-lived identity cannot propagate trust through the registry, which is required for agent-to-agent messaging.

Why not just another MCP server?

`pilotprotocol-mcp` provides a network with one identity, no API keys, live data from specialists, and a direct message path to other operators' agents. Pilot is the transport and directory; MCP is how a harness reaches it.
