PostgreSQL — Full usage demo

Run and query PostgreSQL from an agent — local server lifecycle + psql, any libpq target.

Install

pilotctl appstore install io.pilot.postgres

When to use

When you need a full PostgreSQL server RDBMS — rich SQL, extensions, concurrent clients over a libpq connection — rather than an in-process file db; requires a one-time initdb + start.

Run this first — Confirm the client works (no server needed)

pilotctl appstore call io.pilot.postgres postgres.version '{}'

Expect: the delivered client version, e.g. "psql (PostgreSQL) 17.10"

Worked examples

Create a data directory

pilotctl appstore call io.pilot.postgres postgres.initdb '{"datadir":"/work/pgdata"}'

Expect: a new initialized cluster at /work/pgdata

Start the server

pilotctl appstore call io.pilot.postgres postgres.start '{"datadir":"/work/pgdata","port":"5599"}'

Expect: server accepting connections on 127.0.0.1:5599

Create a database

pilotctl appstore call io.pilot.postgres postgres.createdb '{"port":"5599","dbname":"shop"}'

Expect: database `shop` created, owned by postgres

Create a table, insert, and select

pilotctl appstore call io.pilot.postgres postgres.query '{"uri":"host=127.0.0.1 port=5599 user=postgres dbname=shop","sql":"CREATE TABLE items(id INT PRIMARY KEY, name TEXT); INSERT INTO items VALUES (1,'pen'); SELECT * FROM items"}'

Expect: one row: id=1, name=pen

Describe tables with a psql meta-command

pilotctl appstore call io.pilot.postgres postgres.command '{"uri":"host=127.0.0.1 port=5599 user=postgres dbname=shop","command":"\\dt"}'

Expect: a list of relations including `items`

Good to know

  • Order matters: postgres.initdb once (datadir must be new/empty), then postgres.start before any query.
  • query/command/list take a libpq `uri`, e.g. "host=127.0.0.1 port=5599 user=postgres dbname=shop", not a bare port.
  • The default superuser is `postgres`; connections are 127.0.0.1 only.
  • datadir paths resolve inside the app sandbox, not your shell CWD.
