Redis — Full usage demo

Run Redis from an agent — start a local in-memory store and run any command with redis-cli.

Install

pilotctl appstore install io.pilot.redis

When to use

When you need a fast in-memory key/value store for caching, counters, session state, queues or ephemeral shared data — not for relational queries or durable structured storage.

Run this first — Confirm the client works (no server needed)

pilotctl appstore call io.pilot.redis redis.version '{}'

Expect: the delivered client version, e.g. "redis-cli 8.6.2"

Worked examples

Start a local server

pilotctl appstore call io.pilot.redis redis.start '{"port":"6399","dir":"/tmp"}'

Expect: server daemonized on 127.0.0.1:6399; pidfile/logfile/RDB written under /tmp

Set a key

pilotctl appstore call io.pilot.redis redis.set '{"port":"6399","key":"session:42","value":"active"}'

Expect: OK

Get the key back

pilotctl appstore call io.pilot.redis redis.get '{"port":"6399","key":"session:42"}'

Expect: active

Set a TTL via the raw CLI

pilotctl appstore call io.pilot.redis redis.exec '{"args":["redis-cli","-p","6399","EXPIRE","session:42","60"]}'

Expect: (integer) 1 — the key will auto-delete after 60 seconds

Count keys

pilotctl appstore call io.pilot.redis redis.dbsize '{"port":"6399"}'

Expect: (integer) 1

Good to know

  • You must redis.start a server before ping/set/get/dbsize — only redis.version works with no server.
  • port is a string ("6399"), and each server needs its own port + writable dir.
  • redis.stop does no final save; use redis.exec with SAVE first if you need the RDB persisted.
  • redis.set/get handle plain strings; for lists, hashes, EXPIRE etc. drop to redis.exec with a verbatim argv.
