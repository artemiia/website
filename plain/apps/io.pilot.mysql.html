MySQL — Full usage demo

Run a real MySQL server from an agent — full client/server SQL, no cloud account, no provisioning.

Install

pilotctl appstore install io.pilot.mysql

When to use

When you need a full MySQL server RDBMS — multiple databases, concurrent clients, a wire protocol on a TCP port — rather than an in-process file db; requires a one-time initialize + start.

Run this first — Confirm the binaries work (no server needed)

pilotctl appstore call io.pilot.mysql mysql.version '{}'

Expect: the delivered version, e.g. "mysql Ver 9.7.1 for ... (conda-forge)"

Worked examples

Initialize a data directory

pilotctl appstore call io.pilot.mysql mysql.initialize '{"datadir":"/work/mysql-data"}'

Expect: an initialized datadir at /work/mysql-data

Start the server

pilotctl appstore call io.pilot.mysql mysql.start '{"datadir":"/work/mysql-data","port":"13306"}'

Expect: server listening on 127.0.0.1:13306

Create a database

pilotctl appstore call io.pilot.mysql mysql.createdb '{"port":"13306","dbname":"shop"}'

Expect: database `shop` created (no-op if it exists)

Create a table, insert, and select

pilotctl appstore call io.pilot.mysql mysql.query '{"port":"13306","database":"shop","sql":"CREATE TABLE items(id INT PRIMARY KEY, name VARCHAR(32)); INSERT INTO items VALUES (1,'pen'); SELECT * FROM items"}'

Expect: an aligned ASCII table with one row: 1 | pen

List tables

pilotctl appstore call io.pilot.mysql mysql.tables '{"port":"13306","database":"shop"}'

Expect: SHOW TABLES output listing `items`

Good to know

  • Order matters: mysql.initialize the datadir once, then mysql.start before any query.
  • The initial account is an insecure root@localhost with no password; 127.0.0.1 connections only.
  • port is a string ("13306"); mysql.query needs a `database` that already exists (create it with mysql.createdb).
  • Data directories and dumps resolve inside the app sandbox, not your shell CWD.
